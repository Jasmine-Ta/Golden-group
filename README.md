Disaster Recovery
1. Overview of the Project
This website was created to show how an online platform can handle unforeseen disruptions such as server downtime, hacking attempts, loss of data, and connectivity problems.
The main aim is to create awareness around web security, the need for data protection, being prepared for disasters, and the process of recovering after an incident.

2. Aims of the Project
The key goals of this site are to:
Outline possible threats and risks that could affect a website.Describe the procedures required for effective disaster recovery.Emphasize why consistent backups are essential.Include a practical, interactive checklist for recovery.Deliver content through a clean, professional and easy-to-use design.Ensure the site works well across desktops, tablets and smartphones.

3. Tools and Technologies
The following web technologies were used in development:
HTML5: Used to build the structure and organize all the content on the pages.CSS3: Responsible for styling, including colours, fonts, page layout, animations and responsiveness.
Techniques: Allow the site to automatically adjust to various screen sizes and devices.

4. Core Features of the Website
4.1 Navigation Menu
Contains links to the main sections: Home, Potential Risks, Recovery Plan, and Recovery Checklist.

4.2 Introductory Section
Provides an overview of the disaster recovery plan and outlines its main recovery goals.

4.3 Identification of Risks
Covers typical threats such as:
Failure of serversCyber security attacks Accidental or malicious data loss Electricity or internet outages.

4.4 Recovery Process
Explains the recovery process in five steps:
Detection and identification of the incident.Containment to prevent further damage.Recovery of data and restoration of services.Testing to ensure the website is fully functional.Ongoing monitoring and continuous improvement.

4.5 Backup Strategy
Focuses on why frequent backups, safe storage locations, limited access permissions, and regular restore tests are critical.

4.6 Interactive Checklist
Users can mark off tasks as they are completed. The progress is tracked automatically with JavaScript, and a reset option is available.

4.7 Emergency Support
Includes contact information to reach the site administrator in case of an emergency.

4.8 Mobile-Friendly Layout
Uses CSS media queries to ensure the design remains usable and readable on small screens.

Save the project folder onto your local machine.Open it using Visual Studio Code or any other code editor.Find the file named disaster-recovery.html.Launch the file in any modern web browser.Use the navigation bar to move between sections.Interact with the checklist by checking and resetting items.View the page in different screen sizes to see the responsive design.

7. Testing Procedures
The site should be tested for:
Loading correctly without any errors.Functionality of all navigation links.Accurate progress updates in the checklist.Proper functioning of the reset button.Automatic display of the current year in the footer.Responsive behaviour on mobile and desktop devices.The emergency email link opening the default mail client.

8. Security Notes
This site is for educational purposes and explains disaster recovery concepts. The checklist is only a simulation and does not actually perform backups or system restores.
In a live environment, a complete recovery solution would need encrypted backup storage, strict user access management, server-level recovery protocols, and frequent disaster recovery drills.
The placeholder email address must be updated with a valid administrative contact before the site goes live.

9. Current Limitations
Checklist progress is lost when the page is refreshed.The site cannot automatically detect real website failures.No live database backup or recovery actions are executed.The contact email function relies on the user's email setup.

10. Possible Future Enhancements
Future updates could include:
Implementation of automated and secure backup systems.Ability to save checklist progress using local storage.Real-time monitoring of website uptime.An online form for reporting incidents.Secure login for administrators.Integration with a protected database to store incident logs.

11. Final Summary
This Disaster Recovery Plan website shows how well-organized information, clear recovery steps, and interactive tools can educate users on business continuity and online security.
By combining HTML and CSS the project delivers a responsive, engaging and informative web experience that highlights the value of being prepared for digital disasters.
